# AGENT LESSONS (research-technique memory)
- Best query pattern for pricing: '<service> consulting cost/pricing 2025' -> surfaces pricing pages directly.
- Cite vendor pricing pages for comparable offers (stronger than SEO listicles).
- Use execute_code batching for multi-query sweeps (cheap, mechanical).
- No 'superpowers' skill/plugin present on this host; use hermes-agent + github + grounded-citations instead.
- Bootstrap file is NOT at ~/Downloads; canonical copy at ~/hermes-knowledge/00_bootstrap/.
- Local-business audits: lead with a raw-HTML signal scan (`<form>` / `wa.me` / `tel:` / `mailto:` counts) — it turns "the site looks weak" into a citable OBSERVED defect (e.g. "the page says 'use the form above' but the served HTML has no form").
- Before launching new discovery, RECONCILE the ledgers: the local engine had 32 deep audits but an empty CONTACTS/OUTREACH/OPPORTUNITIES ledger — the bottleneck was converting research into queued outreach, not more research.
- India B2B/B2C local outreach channel = WhatsApp / phone / Instagram DM. Email exists for only ~1/3 of small businesses. Do not design around cold email.
- For WhatsApp/email outreach, ALWAYS convert the final approved drafts into one-tap `wa.me/<digits>?text=<urlencoded>` / `mailto:?subject=&body=` links. Copy-paste messages make founder send-time 15-25 min/item; pre-filled links make it ~1.5-2 min/item. URL-encode with urllib.parse.quote and assert an encode→decode roundtrip — a malformed link silently kills the send.
- Published contact routes DECAY. Re-verify a route on the live site immediately before sending; a stale number on first contact destroys the credibility the "specific observed defect" opener depends on. Never "improve" a number you cannot re-confirm — flag it UNVERIFIED and use the verified channel.
- Browser backend works on this host as of 2026-10-03 (earlier libatk blocker cleared).
- Home-interiors / modular-kitchen and study-abroad are HIGH-VALUE local niches (₹2–20L interiors ticket; ₹25k–1.5L+ per overseas enrolment) and were untouched by Batches 1–2. Prefer niches where ONE extra customer is economically meaningful.
- A THIRD leak archetype exists beyond "slow response": the ABSENCE of a capture surface (no form/WhatsApp) and a DEAD web presence (listed site that does not resolve). Both are citable from raw HTML/DNS and both are easy to fix — strong openers.
- Some Indian SMB sites serve different bytes by User-Agent (westernwings.in returned 0 bytes to a desktop UA curl but full HTML to an iPhone UA). Always fetch with a mobile UA so a legacy site is not wrongly recorded as empty.
- Legacy sites may be `iso-8859-1`: read curl output with `errors="replace"` or the decode throws a UnicodeDecodeError mid-scan and aborts the whole batch.
- Beware NAME COLLISIONS across states: "Disha Interiors" (Hyderabad dishahome.com) vs Mumbai/Baramati; "Western Wings" (Hyderabad westernwings.in) vs a Mumbai "Western Wings & Immigration Services Pvt Ltd". Verify the entity against the city/address before attributing an owner.
- PRE-SEND RE-VERIFICATION is mandatory and produces real attrition: a live re-check of only 20 previously drafted items killed 6 citable defects (the sites now serve working forms) and 1 whole route (Dr White Dental's published mailboxes are gone). Assume ~25-30% of a stale batch is no longer sendable. A stale defect opener is worse than no draft — it discredits you on first contact.
- NEVER turn a transient fetch failure into a citable defect. westernwings.in returned 200, then HTTP 000 on repeat, then 200 again the same day; a draft built on "your site is down" would have been a false claim in the first message. DNS-resolving-but-not-serving is a flaky-reading state, not evidence — cite only the defects confirmed in the successful fetch (0 form / 0 tel: / 0 viewport / © year), and drop any number you cannot reproduce (the "1001px table width" was not in the re-fetched bytes).
- Chief-of-Staff must INDEPENDENTLY re-fetch the top defects a leaf worker cites before accepting a batch. A worker's summary is a self-report: it claimed 14 send-ready items and 14 validated mailto links, and the defects checked out — but its A8 draft contained a claim that failed on live re-check the same day. Verify the deliverable on disk and spot-check the strongest claims with your own fetch.
- Citable-defect claim sizes matter: <form> count, wa.me/tel:/mailto: presence and a missing viewport meta are all reproducible from one mobile-UA fetch. Prefer those over "the page looks weak" or any measurement not visible in the current bytes.
